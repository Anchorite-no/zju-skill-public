# lib/ 组件边界

当前分层、模块归属和 CLI 边界见 [架构](../dev/architecture.md)。本目录里的模块属于同一套系统，各命令复用现有配置、认证、传输和业务组件。

## 唯一职责

| 组件 | 职责 |
|---|---|
| profile | 读取统一配置；业务模块不另设账号文件 |
| core/http | HTTP、Cookie、连接池 |
| webvpn/transport | 根据模块声明组装直连/WebVPN 与认证上下文 |
| zjuam | CAS 密码认证、TGT 与 service 票据交换 |
| 各站点 client/index | 站点特有回跳、会话、token 与请求适配 |
| 各业务文件 | 接收现有客户端，实现本系统的查询和操作 |
| 各模块 cli | 参数校验、任务生命周期，调用同一业务实现 |
| lib/cli.ts | 汇总模块注册，不登录、不执行业务 |

所有 CAS 模块的工厂调用 `openContext` 并注入 CAS 组件。内部会话准备只在站点缓存缺失或失效时执行，不额外预检 CAS。WebVPN 缓存 ticket 直接使用，明确被网关拒绝后恢复。`fresh` 是明确的刷新请求。站点 Cookie 和 App token 仍各自保存，因为 CAS 票据不能直接替代它们。

业务用户调用一个任务命令即可。`session` 子组只用于维护；直接导入模块函数与 CLI 共用代码，不构成额外插件、安装层或第二套登录执行器。开发时先复用已有组件，再决定是否需要新的站点适配。

## 生命周期与写入

CLI 通过模块工厂创建任务所需客户端，传给业务函数，结束后关闭。业务函数不得自行读取账号或创建第二个登录客户端。内部职责见 [学在](xuezai/README.md)；其他模块的使用和限制见对应 references。

业务写入由所属模块检查授权，调用 `core/journal.fileJournal` 记录操作，并按该平台协议回查。共享日志只负责落盘，平台状态语义由业务模块解释。已有模块未覆盖的部分应明确记录，不新增平行执行层。

CLI 用法在 references；实际请求、端点和协议细节在各模块 README；flows 保存定制化的多步骤工作流。普通文件读取、总结和排版直接由 AI 完成，不再包装成重复命令。
