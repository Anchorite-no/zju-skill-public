# 通知公告 请求与协议

CLI 用法见 [通知](../../references/notice.md)。本文件记录来源表、各适配器的请求与解析细节，供开发和排障使用。

- 声明：`auth=cas network=campus writes=false`。整个 `zju.edu.cn` 默认经 WebVPN，逐站标注表 `hosts.json` 里实测公网可达的主机（69 个里 50 个）列进 `publicHosts` 直连；直连不通，或者被网站群挡到「无权访问」页（`/nopermit_zjusub.jsp`，只给校内看的页面对校外这样做），这个主机在这一次命令里改回 WebVPN（`lib/webvpn/transport.ts`）。表由 `scripts/notice/hosts.ts --via <外部主机>` 从校外实测生成（2026-10-09 在 Innovation 桌面端加，2026-10-31 同步过来），来源表或学院名录变了要重跑；`notice sources` 的结果里每个来源带 `network`。教务网通知借用 `zdbk` 的会话（公网直连，要统一身份认证）。没确认的一点是网站群的列表页对校外访问会不会少列只给校内看的条目。
- 代码：`lib/notice/{index,sources,identity,article,types,cli}.ts`、`adapters/{webplus,zdbk,kyjs}.ts`、学院名录 `colleges.json`（由 `scripts/notice/colleges.ts` 生成）、逐站标注表 `hosts.json`（由 `scripts/notice/hosts.ts` 生成）· CLI：`zju notice …` · 已读记录：`data/notice/seen.json` · 识别出的学院：`data/notice/identity.json` · 教务网完整标题缓存：`data/cache/zdbk-notice-titles.json`
- 端点最近核对：教务网 2026-09-17/18；webplus 各站、学院名录与 kyjs 2026-10-06。

## 结构

- `sources.ts` 是来源表：站点、栏目、是否默认、是否进增量、是否只面向本科生或研究生。加一个 webplus 站点或栏目只改这里。数组顺序是合并去重时的优先级。
- `colleges.json` 是各学院官网的栏目，生成的，不手改；`identity.ts` 判断使用者的类别和学院，把本人学院当作一个来源排在最前。见下面「学院官网」一节。
- 适配器按平台家族写，不按站点写：`webplus` 通吃网站群站点，`zdbk` 是教务网，`kyjs` 只管竞赛系统的正文。
- `article.ts` 解析正文页，不分来源。
- `index.ts` 负责选来源、并发读取、合并去重、取正文、增量记录。每个 webplus 栏目和教务网各是一个独立任务：一个失败不影响其他，失败的进 `sourceErrors`。
- 一次命令里按需打开两种会话：教务网（`openZdbk`）和校内上下文（`openContext`，hosts=`zju.edu.cn`）。只查学工部时不登录教务网。

## webplus 网站群

浙大的学校主页、综合服务网和绝大多数部处官网都是苏迪 webplus（页面带 `/_upload/`、`list.htm`、`page.htm`、`wp_articlecontent`）。

- 列表 `GET /<栏目>/list.htm`，第 N 页 `list<N>.htm`（学工部、图书馆的后续页会 302 到 `list<N>.psp`，照跟）。栏目可以是数字（`76425`）或路径名（`zhfw_jyjx`、`qbgg`）。
- 分页条 `#wp_paging_w<n>` 里有 `<em class="all_pages">`、`all_count`、`per_count`、`curr_page`。每页条数各站不同：多数 14，综合服务网 24，研工部 10。
- 列表项模板各站不同，已见：`li.right-list-item > a > p + div.time > span.y`（本科生院）、`li.news > span.news_title a + span.news_meta`（学工部、图书馆、信息技术中心）、`li > a + span.date`（研工部）、`li > a + 裸日期文本`（综合服务网）、`li.list-item > a > div.content h3[title] + div.date`（研究生院）、`div.jzlb > div.btt3 a + div.fbsj4`（电气学院）、整条包在链接里的 `a > p.tit3 + span.fbdate`（教育学院）和 `a > div span + h3 + p`（人工智能学院）。
- 条目的认法不按站分支，也不认标签名：用 parse5 解析页面，按文档顺序收集最后一个分页条之前的链接（分页条里的翻页链接不算），从最后一个链接往上找，第一层「同名兄弟元素里含链接的不少于本页条数」的就是条目，取最后 N 个。N 由分页条算出（非末页为 per_count，末页为 all_count 减去前面各页），找不到就报错。链接本身并排时，只有日期写在链接里才把链接当条目；本页只有一条时没有兄弟可比，取到 li/tr 或能读出日期的那一层。导航栏、侧栏都在更前面，不会混进来。
- 标题依次取条目里的 `title` 属性（链接上或里面的标题元素上）、链接里的 `<h1-6>`、class 含 tit/bt 的元素、`<p>`、链接文字（日期写在链接里时去掉）。日期取条目里的短文本（24 字以内的元素文字或文本节点，去掉括号和「发布时间：」）：完整日期 `2026-09-30`、`2026/09/30`、`2026年9月30日`，两位年 `22-09-05`，只到月份的 `2026-09`（日从文章地址取，地址对不上月份时找单独的日数字），月日加单独的年份；都没有时用文章地址里的年月日。
- 文章 `/<年>/<月日>/c<栏目>a<文章号>/page.htm`。文章号全站群唯一递增（2026-09-30 约 321 万）；同一篇挂在几个栏目时栏目号不同、文章号相同（综合服务网「教育教学」`c4905a…` 与「即时更新」`c5074a…`），去重按文章号。地址里的日期是创建日，可能比列表上的发布日期早一天。条目也可能直接指向外站、附件或内网地址。
- 顺序：多数栏目按时间由新到旧，个别置顶或错位一两天。读取以每页末尾三条里最新的日期判断读到了哪里：早于所需范围、或已凑够条数且后面不会再有更新的，就停。给了 `since` 最多读 40 页，只给关键词时往回一年、最多 12 页；到页数上限还没读完的记进 `searchedBackTo`。本科生院两栏几乎每条都置顶、顺序不代表时间，在来源表里标 `unordered`，固定读完全部页（各 4–5 页）。
- 需要统一认证的站点（信息技术中心）：`list.htm` 302 到 `list.psp`，再到 `zjuam.zju.edu.cn/cas/login?service=http://itc.zju.edu.cn/90618/list.psp`。请求落在 CAS 登录页时取出 service，交给 `ctx.zjuam.loginService`，同一上下文重取；同站点的并发请求共用一次委托。文章页同理（service 是该文章的 `page.psp`）。实测委托 2–5 秒。
- 不存在或无权查看的文章返回 200 的提示页（`<title>提示信息</title>`，`.wp_error_msg` 里是「无效的文章地址」），按错误处理。
- 只读请求最多发三次（`read.ts` 的 `patiently`），校内页面和教务网的列表、详情都走它。前两次只等 3.5 秒，超时立刻换一条连接重发；第三次用连接默认的 10 秒。连接被断开等其他传输错误隔 0.8、1.6 秒再发（官网偶发断开连接）。
  - 原因：从校外进校内的新连接有几个百分点会一直不回应。一次默认列表约 60 个请求，网络正常时 1 秒左右；原来卡住的那个请求要等满 10 秒，整条命令约 12 秒。2026-10-07 本机改动前 14 次里 8 次约 12 秒，改动后 32 次里 18 次约 4.3 秒、其余约 1.1 秒，结果都完整。
  - 登录、WebVPN 重登这些步骤不走它，仍用默认超时。

## 学院官网（colleges.json、identity.ts）

各学院官网也是 webplus，但站点结构各不相同，栏目不手写：`node scripts/notice/colleges.ts` 从学校主页的学院（系）名录出发自动生成 `colleges.json`，学院改版或栏目失效时重跑（全部约 4 分钟；参数给学院名里的文字时只重查这些学院，其余保留）。脚本每步的取舍会打印出来，改规则后看报告。

- 名录：`https://www.zju.edu.cn/xywxw/list.htm`（学校主页是前端渲染，数据在页面脚本的 `list._college` 里），46 个学院（系）和各自的官网地址。
- 站点：学院首页常是语言选择页或 meta refresh 跳转页，中文站在 `/xxcn`、`/chinese`、`/csen` 这类子路径下；不少学院另有办公网（`office.<学院>`、`/xxoffice`、`/xxbg`，计算机学院是另一个域名 `cspo`），学生通知往往在办公网。规则：中文栏目链接不少于 6 个的页面才算站点；选择页下取栏目最多的同站入口作主站，办公网按名字、地址识别，选择页上指向另一个域名的入口也算。
- 栏目：站点首页所有指向本站 `…/list.htm` 的链接，名字像通知的（通知、公告、本科、研究生、学生、评奖、资助、讲座、就业等）逐个打开，用上面的通用解析器读第一页，读得出条目才算。上级栏目取列表页的面包屑（「当前位置」后的链接），没有面包屑时取导航里外层 `li` 的首个链接。
- 取舍：最新一条早于 400 天的不要；栏目自己叫招生、新闻、动态、风采、简介、下载等的不要；栏目或上级栏目属于人事、招聘、师资、校友、工会、党建、科研、继续教育、因公出国的不要（学生、本科、研究生名下的党建和就业招聘除外）；内容已被另一栏覆盖的不要（在对方第一页的时间范围内，自己的条目八成以上都在对方里，条数多的优先留）；最多留最近更新的 12 栏。
- 受众：栏目或上级栏目名里有「本科」记为本科生，有「研究生、硕士、博士」记为研究生，否则通用。
- 同名栏目带上上级栏目名（`本科生教育·最新通知`），还同名的标出办公网。栏目可能分布在主站和办公网，每个栏目带自己的站点地址（`base`），任务键和已读记录的键里也带站点。
- 2026-10-06 的结果：46 个里收录 44 个、392 栏（本科生 62、研究生 78、通用 252），21 个学院有栏目在办公网或子站上，中位数 12 栏；管理、物理、网安、生工食品、环资、药学院只挑到 1–2 栏。没收录的：社会学系（不是 webplus）、医学院（主站上没有可读的学生通知栏）。结果没有逐个学院人工核对。
- 使用者是谁（`identity.ts`）：类别取加密账号配置的 `student_level`，没填按学号首位（3 本科，1、2 研究生）。学院取加密账号配置的 `college`；没填时本科生从教务网的课表响应里读（`zdbk/kbcx.ts` 的 `studentInfo`，两次请求），记在 `data/notice/identity.json`，30 天内不再问。研究生不在本科教务网里，要填 `college`。学院名和名录按全称、包含、简称（`core/match.ts` 的 `abbreviates`）比对，对不上或对上多个时不猜，结果里的 `profile.hint` 说明。只点名来源表里的来源时不识别学院，也就不碰教务网。
- 合并顺序：本人学院排在来源表之前。学院转发校级通知时会加上院内安排，标题相同、日期相近的留学院那条。

## 正文解析（article.ts）

- 正文容器依次认：教务网 `div.news_con`、`wp_articlecontent` / `v_news_content` / `#vsb_content`、`col-lg-offset-2 col-md-offset-1`、`<article>`。信息技术中心的模板把导航栏也叫 `news_con`：页面同时有 `wp_articlecontent` 且不在 `news_con` 里面时，以 `wp_articlecontent` 为准。
- webplus 文章窗口是 `[portletmode=simpleArticleAttri]`，标题和「发布者 / 来源 / 时间」一行排在正文之前，各站 class 不同（`arti_metas`、`art-summary`、`news-tow`），统一取窗口里正文之前的文字来解析。综合服务网这一行有「来源:基本建设处」，作为 publisher；其他站点这一行只有发布人姓名，publisher 用来源表里的单位名。
- 教务网详情：`h3.text-center` 标题、`.news_title1` 里发布人/时间/浏览人数、`div.news_con` 正文。
- webplus 正文里的 PDF 以 `<div pdfsrc>` 内嵌，解析为附件。原始附件型通知保留链接，标 attachment-only，不假装读过 DOC/PDF 内容。
- 无可识别正文时回退 meta description 并标 summary-only；什么都没有标 unavailable。招聘系统（ehr，前端渲染）、计财处（FastAdmin）的页面目前落在这里。

## 合并与去重

- 同一来源内按编号去重（教务网 `xwbh`、网站群 `wp-<文章号>`、其余为链接）。
- 不同来源之间：标题去掉开头的【…】、「本科生院」「浙江大学」前缀和标点后，短的整段出现在长的里（短的至少 8 个字），且发布日期相差不超过 14 天，视为同一条，留来源表里排在前面的。教务网列表标题被截断，所以用「包含」而不是「相等」。只比前 12 个字的旧办法不够：「关于做好2026-2027学年…」开头的通知各部门都有。
- 合并后按日期由新到旧，同一天的保持来源表顺序。

## notice view

- `--url` 按主机分派：`kyjs` 走接口；教务网主机用教务网会话；其余经校内上下文取页面。链接属于已接来源时带上来源名。
- `--title` 在默认栏目加增量栏目里按标题检索：先试原标题，再试标题里最长的两段连续文字，本地再按去标点后的标题比对；不唯一时返回候选。

## notice new 与已读记录

`data/notice/seen.json`：

```json
{ "sources": { "zdbk": { "checkedAt": "2026-10-06T10:40:24.970Z", "seen": { "<编号>": "2026-09-30" } }, "xgb/53388": { "checkedAt": "…", "seen": {} } } }
```

- 键是任务：教务网为 `zdbk`，网站群为 `<来源 id>/<栏目>`。`seen` 是编号 → 发布日期。
- 每个任务读发布日期不早于「上次检查的 7 天前」的条目（第一次为最近 7 天，最多回看 45 天），其中不在 `seen` 里的是新的。回看 7 天是为了补发和改期的通知；起点只会向后移，所以旧条目不会重新冒出来。
- 各任务的新条目合并去重，一次最多列 100 条。没列出的条目（以及并到它们名下的重复条目）不记为已读，下次调用继续。
- 读取失败的任务不更新记录。整份记录在结果组装完之后一次写入。`seen` 里超过 60 天的条目清掉。
